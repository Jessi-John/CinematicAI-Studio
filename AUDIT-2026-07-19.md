### H1 — Production secret enforcement is fail-open when `NODE_ENV` is unset or non-lowercase
- **Files:** `backend/src/config/env.ts:257,274,294,311` (raw checks) vs `:208` (normalized)
- **Root cause:** The module normalizes `NODE_ENV` (`(process.env.NODE_ENV || 'production').toLowerCase().trim()`) for the `skipStrict` decision, but the four strict secret gates (API_SECRET, ADMIN_API_KEY, JWT_SECRET, REDIS_PASSWORD) use raw `process.env.NODE_ENV === 'production'` comparisons; the file's own `isProduction()` helper (line 368) is unused internally.
- **Impact:** With `NODE_ENV` unset (code default = production) or `Production`/`PRODUCTION`: strict mode is on yet all four gates are bypassed — API/JWT secrets become random per-process values (auth breaks across restarts/replicas) and `REDIS_PASSWORD` falls back to `''` (unauthenticated Redis in a production-tagged deploy, no error).
- **Fix:** compute `const isProd = normalizedEnv === 'production'` once and use `isProd && !skipStrict` for all four gates.

### H3 — Circuit-breaker half-open probe lock leaks permanently on pipeline abort (both providers)

### H6 — Worker emits terminal `'error'` SSE event on every failed attempt, killing the stream before BullMQ retries

### H7 — Orphaned pipeline attempt shares checkpoint keys with the BullMQ retry (state corruption / duplicate processing)

### H10 — Webhook SSRF: IPv4-mapped IPv6 literals bypass the entire blocklist — **amplified after live probe**
- **File:** `backend/src/services/webhook.ts:72-94`
- **Root cause:** Only `::ffff:127.x` mapped forms are blocked; `http://[::ffff:10.0.0.1]/`, `::ffff:192.168.1.1`, `::ffff:169.254.169.254` (cloud metadata), and hex forms pass. Raw-IP hosts skip DNS resolution so no re-check occurs downstream. `fe80::/10` check misses `fe81`–`febf`.
- **Live probe (this session, executed against the real `isUrlBlocked`):** `::ffff:10.0.0.1` → **not blocked**; `::ffff:192.168.1.1` → **not blocked**; `::ffff:169.254.169.254/latest/meta-data` → **not blocked**; hex form `::ffff:0a00:0001` → **not blocked**; `fe85::1` → **not blocked**; even `::ffff:127.0.0.1` → **not blocked** (the code's own loopback-mapped check does not fire). IPv4 natives `127.0.0.1` and `10.1.2.3` are blocked correctly.
- **Impact:** Authenticated users can register webhook URLs reaching internal RFC1918 services, loopback, and cloud metadata endpoints — full SSRF despite otherwise careful DNS pinning.
- **Fix:** detect IPv4-mapped/compatible IPv6 (decimal and hex forms) and delegate to the IPv4 range table; complete the `fe80::/10` match; add regression tests for every probe above.

### H11 — Token-budget refund corrupts counters across UTC day/month rollover (negative counters → budget bypass)

### H26 — Full-story regeneration always times out at the standard 10-episode configuration; client gets an empty response; orphan keeps burning tokens (verified live)
- **Files:** `backend/src/services/story-regeneration.ts:11` (`PIPELINE_TIMEOUT_MS = 5 * 60 * 1000`); `backend/src/server.ts:93` (`req.setTimeout(REQUEST_TIMEOUT_MS)` default 5 min, then `req.destroy()`); `lib/query/stories.ts:171` (client timeout also 5 min)
- **Root cause:** The regeneration wall-clock is 5 minutes, but the real 10-episode pipeline takes ~7 minutes (live: initial generation ~7 min; regeneration `WATCHDOG_FIRED elapsedMs:300003`). - **Fix:** scale the regeneration timeout with `episodesPerStory` (or reuse the worker's 45-min watchdog value); make it `< REQUEST_TIMEOUT_MS` with clear headroom so the 504 JSON always reaches the client; raise the client mutation timeout accordingly; apply the H7 attempt-fencing so the orphan's work is abandoned (or stream progress via SSE like initial generation).

## 10. Architecture & design observations (verified, non-blocking)

- **BFF + direct dual exposure:** In production, Caddy routes `/api/*` directly to the backend (Caddyfile:43), bypassing the Next BFF; in local dev the browser hits the BFF. The two paths have subtly different behavior (BFF allowlist, header sanitization, 5-min/2h timeouts). Deliberate defense-in-depth, but it doubles the integration surface — M22 (`/api/v1`) and M39 (content-length) are symptoms. Document both topologies explicitly in DEPLOYMENT.md.
- **Single Redis as multi-plane dependency:** queues, rate limits, JWT blacklist, SSE pub/sub, token budgets, and concept registry all share one Redis. H15/H19 show divergent failure behavior per consumer; define a uniform fail-open/fail-closed policy per feature in one place.
- **Pipeline checkpointing is sophisticated but unfenced** (H7) — attempt-token fencing is an architectural fix, not a local one.
- **Monorepo without workspaces:** independent lockfiles, dual husky installations (H24), script-maintained version sync (M68). Consider npm workspaces to eliminate the drift class.
- **Generated-content post-processors can damage content** (M11, M12, M14): deterministic text mutators run after expensive AI generation without revalidation. Centralize "accept" criteria and re-run them after every mutation.
